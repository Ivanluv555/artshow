## 🔴 严重问题（P0 - 阻塞业务运营）

### 1. 支付系统完全缺失 - 商业模式无法闭环

**问题描述：**

系统有完整的订单流程，但**没有任何支付系统集成**：
- `order` 表只有 `status` 字段，没有 `payment_method`、`payment_time`、`transaction_id` 等支付相关字段
- 没有 `payment` 或 `transaction` 表记录支付流程
- 订单状态从 `pending` 变为 `paid` 没有实际的支付操作
- 不支持任何支付方式（支付宝、微信支付、银行卡等）

**当前流程的荒谬之处：**
```java
// OrderService.java - 用户可以"凭空"支付订单
public void payOrder(Long orderId) {
    order.setStatus("paid");  // 😱 没有实际支付，直接标记为已支付！
    orderRepository.save(order);
}
```

**业务影响：**
- ❌ 用户可以不付款就获得商品/课程（只需调用API修改状态）
- ❌ 商家无法收到款项
- ❌ 平台无法抽成
- ❌ **整个电商和课程付费模式完全失效**

---

**调整建议：**

1. **创建支付系统核心表：**

```sql
-- 支付记录表
CREATE TABLE `payment` (
    `payment_id` BIGINT NOT NULL COMMENT '支付ID（雪花ID）',
    `order_id` BIGINT NOT NULL COMMENT '订单ID',
    `user_id` BIGINT NOT NULL COMMENT '用户ID',
    `amount` DECIMAL(10,2) NOT NULL COMMENT '支付金额',
    `payment_method` VARCHAR(20) NOT NULL COMMENT '支付方式：alipay, wechat, card',
    `transaction_id` VARCHAR(100) DEFAULT NULL COMMENT '第三方支付平台交易号',
    `status` VARCHAR(20) DEFAULT 'pending' COMMENT '支付状态：pending-待支付, success-成功, failed-失败, refunded-已退款',
    `paid_at` TIMESTAMP NULL DEFAULT NULL COMMENT '支付完成时间',
    `refunded_at` TIMESTAMP NULL DEFAULT NULL COMMENT '退款时间',
    `created_at` TIMESTAMP NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`payment_id`),
    KEY `idx_order_id` (`order_id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_transaction_id` (`transaction_id`),
    CONSTRAINT `payment_ibfk_1` FOREIGN KEY (`order_id`) REFERENCES `order` (`order_id`)
);
```

2. **集成第三方支付：**
   - 支付宝支付：使用支付宝SDK
   - 微信支付：使用微信支付SDK
   - 实现支付回调接口，验证支付结果

3. **支付流程重构：**

```java
// PaymentService.java
@Transactional
public PaymentResult createPayment(Long orderId, String paymentMethod) {
    // 1. 查询订单，验证状态
    Order order = orderRepository.findById(orderId)
        .orElseThrow(() -> new BizException("订单不存在"));
    
    if (!"pending".equals(order.getStatus())) {
        throw new BizException("订单状态不正确");
    }
    
    // 2. 创建支付记录
    Payment payment = new Payment();
    payment.setOrderId(orderId);
    payment.setUserId(order.getUserId());
    payment.setAmount(order.getTotalPrice());
    payment.setPaymentMethod(paymentMethod);
    payment.setStatus("pending");
    paymentRepository.save(payment);
    
    // 3. 调用第三方支付接口
    String payUrl = thirdPartyPaymentService.createPayment(payment);
    
    return new PaymentResult(payment.getPaymentId(), payUrl);
}

// 支付回调
@Transactional
public void handlePaymentCallback(String transactionId, PaymentCallbackData data) {
    // 1. 验证签名
    if (!thirdPartyPaymentService.verifySignature(data)) {
        throw new BizException("签名验证失败");
    }
    
    // 2. 更新支付记录
    Payment payment = paymentRepository.findByTransactionId(transactionId)
        .orElseThrow(() -> new BizException("支付记录不存在"));
    
    payment.setStatus("success");
    payment.setPaidAt(new Date());
    paymentRepository.save(payment);
    
    // 3. 更新订单状态
    Order order = orderRepository.findById(payment.getOrderId())
        .orElseThrow(() -> new BizException("订单不存在"));
    order.setStatus("paid");
    orderRepository.save(order);
    
    // 4. 如果是课程订单，自动开通课程访问权限（见问题4）
}
```

**优先级：** 🔴 **P0 - 最高优先级**，没有支付系统，整个商业模式无法运转。

### 2. 商品进货管理缺失 - 库存无法正常补充

**问题描述：**

虽然第一次调整中已经识别到库存增加的并发问题，但根本问题是：**系统缺少完整的进货/入库管理模块**。

当前状态：
- ❌ 没有 `stock_in` 或 `inventory_log` 表记录进货历史
- ❌ 商家通过 `updateProduct` 直接修改库存数值（`stock=150`），存在并发冲突风险
- ❌ 无法追踪：谁、什么时候、进了多少货、进货成本
- ❌ 无法区分：销售扣减 vs 进货增加 vs 盘点调整

**业务影响：**
- 商家无法准确管理库存
- 财务无法核算成本
- 审计无法追溯库存变更
- 并发操作可能导致库存数据错误

**调整建议：**

1. **创建库存变更日志表：**

```sql
CREATE TABLE `inventory_log` (
    `log_id` BIGINT NOT NULL COMMENT '日志ID（雪花ID）',
    `product_id` BIGINT NOT NULL COMMENT '商品ID',
    `change_type` VARCHAR(20) NOT NULL COMMENT '变更类型：purchase-销售, restock-进货, return-退货, adjust-盘点调整',
    `quantity_change` INT NOT NULL COMMENT '数量变化（正数=增加，负数=减少）',
    `before_stock` INT NOT NULL COMMENT '变更前库存',
    `after_stock` INT NOT NULL COMMENT '变更后库存',
    `order_id` BIGINT DEFAULT NULL COMMENT '关联订单ID（销售时）',
    `cost_price` DECIMAL(10,2) DEFAULT NULL COMMENT '进货成本（进货时）',
    `operator_id` BIGINT NOT NULL COMMENT '操作人ID',
    `reason` VARCHAR(500) DEFAULT NULL COMMENT '变更原因',
    `created_at` TIMESTAMP NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`log_id`),
    KEY `idx_product_id` (`product_id`),
    KEY `idx_change_type` (`change_type`)
);
```

2. **实现进货接口：**

```java
// ProductService.java
@Transactional
public void restockProduct(Long productId, Integer quantity, BigDecimal costPrice, String reason) {
    if (quantity <= 0) {
        throw new BizException(ResultCodes.INVALID_PARAM, "进货数量必须大于0");
    }
    
    Product product = productRepository.findById(productId)
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND, "商品不存在"));
    
    // 权限检查：只有商家本人或管理员可以进货
    Long currentUserId = UserContext.getUserId();
    if (!product.getMerchantId().equals(currentUserId) 
        && !UserContext.hasRole(UserRole.ADMIN)) {
        throw new BizException(ResultCodes.FORBIDDEN, "无权进货");
    }
    
    // 记录变更前库存
    int beforeStock = product.getStock();
    
    // 使用原子操作增加库存
    int affectedRows = productRepository.addStock(productId, quantity);
    if (affectedRows == 0) {
        throw new BizException(ResultCodes.INTERNAL_ERROR, "库存更新失败");
    }
    
    // 记录库存日志
    InventoryLog log = new InventoryLog();
    log.setProductId(productId);
    log.setChangeType("restock");
    log.setQuantityChange(quantity);
    log.setBeforeStock(beforeStock);
    log.setAfterStock(beforeStock + quantity);
    log.setCostPrice(costPrice);
    log.setOperatorId(currentUserId);
    log.setReason(reason);
    inventoryLogRepository.save(log);
}
```

3. **在销售时也记录日志：**

```java
// OrderService.createOrderFromCart() 中
for (Orderitem item : orderItems) {
    // 扣减库存后，记录日志
    InventoryLog log = new InventoryLog();
    log.setProductId(item.getProductId());
    log.setChangeType("purchase");
    log.setQuantityChange(-item.getQuantity());
    log.setOrderId(order.getOrderId());
    log.setOperatorId(order.getUserId());
    inventoryLogRepository.save(log);
}
```

**优先级：** 🔴 **P0 - 高优先级**，商家无法正常补充库存，影响业务持续运营。

## 🟠 重要问题（P1 - 影响核心业务）

### 3. 商家和讲师审核流程形同虚设

**问题描述：**

虽然 `merchant` 和 `instructor` 表都有 `status` 字段（pending, active, suspended），但：
- ❌ 创建商家/讲师时默认 `status='pending'`，但没有审核接口
- ❌ 没有管理员审核通过/拒绝的API
- ❌ `pending` 状态的商家仍然可以发布商品，讲师仍然可以发布课程
- ❌ 没有审核记录表，无法追溯谁审核的、审核理由

**当前代码漏洞：**
```java
// ProductService.addOneProduct() - 没有检查商家状态
public Product addOneProduct(ProductDTO product) {
    // 😱 直接创建商品，不管商家是否通过审核
    return productRepository.save(nProduct);
}

// CourseService.addCourse() - 没有检查讲师状态
public Course addCourse(CourseDTO course) {
    // 😱 直接创建课程，不管讲师是否通过审核
    return courseRepository.save(nCourse);
}
```

**业务影响：**
- 未经审核的商家可以发布商品（可能是假冒伪劣、违规内容）
- 未经审核的讲师可以发布课程（可能资质不符、内容违规）
- 平台无法进行资质审核，存在法律风险

**调整建议：**

1. **创建审核记录表：**

```sql
CREATE TABLE `merchant_review` (
    `review_id` BIGINT NOT NULL,
    `merchant_id` BIGINT NOT NULL,
    `reviewer_id` BIGINT NOT NULL COMMENT '审核人ID（管理员）',
    `status` VARCHAR(20) NOT NULL COMMENT 'approved-通过, rejected-拒绝',
    `reason` TEXT COMMENT '审核意见',
    `reviewed_at` TIMESTAMP NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`review_id`),
    KEY `idx_merchant_id` (`merchant_id`)
);

CREATE TABLE `instructor_review` (
    `review_id` BIGINT NOT NULL,
    `instructor_id` BIGINT NOT NULL,
    `reviewer_id` BIGINT NOT NULL,
    `status` VARCHAR(20) NOT NULL,
    `reason` TEXT,
    `reviewed_at` TIMESTAMP NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`review_id`),
    KEY `idx_instructor_id` (`instructor_id`)
);
```

2. **实现审核接口：**

```java
// MerchantService.java

@Transactional

}
```

3. **在发布商品/课程时检查状态：**

### 4. 付费课程权限控制缺失 - 用户可以绕过购买直接学习

**问题描述：**

虽然课程报名时检查了是否购买（`CourseEnrollmentService.enrollCourse()`），但：
- ❌ 用户报名后，访问课程章节（`course_outline`）时**没有任何权限检查**
- ❌ 恶意用户可以直接调用 `/chapter/{chapterId}` 接口查看付费课程内容
- ❌ 课程内容API（`ChapterService.queryChapter`）没有验证用户是否已报名

**当前代码漏洞：**
```java
// ChapterService.java
public Chapter queryChapter(Long chapterId) {
    // 😱 任何人都可以查看任何章节，无需报名或购买
    return chapterRepository.findById(chapterId)
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND));
}
```

**业务影响：**
- ❌ 付费课程可以被免费学习
- ❌ 讲师收益受损
- ❌ 平台付费模式失效

**调整建议：**

```java
// ChapterService.queryChapter() 重构
public Chapter queryChapter(Long chapterId) {
    if (chapterId == null) {
        throw new BizException(ResultCodes.NULLPOINT);
    }
    
    Chapter chapter = chapterRepository.findById(chapterId)
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND, "章节不存在"));
    
    // 1. 查询章节所属课程
    Long courseId = chapter.getCourseId();
    Course course = courseRepository.findById(courseId)
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND, "课程不存在"));
    
    // 2. 如果是付费课程，检查权限
    if ("paid".equalsIgnoreCase(course.getType())) {
        Long userId = UserContext.getUserId();
        
        // 检查是否已报名
        UserCourseEnrollment enrollment = enrollmentRepository
            .findByUserIdAndCourseId(userId, courseId);
        
        if (enrollment == null) {
            throw new BizException(ResultCodes.FORBIDDEN, 
                "您未报名该课程，无法查看课程内容");
        }
        
        // 额外检查：是否已购买（防止数据不一致）
        boolean hasPurchased = orderitemRepository
            .existsPaidCourseByUserIdAndCourseId(userId, courseId);
        
        if (!hasPurchased) {
            throw new BizException(ResultCodes.FORBIDDEN,
                "您未购买该课程，无法查看课程内容");
        }
    }
    // 免费课程：无需检查，直接返回
    
    return chapter;
}
```

**批量查询也需要过滤：**
```java
// ChapterService.queryCourseChapters()
public List<Chapter> queryCourseChapters(Long courseId) {
    Course course = courseRepository.findById(courseId)
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND));
    
    // 如果是付费课程，检查权限
    if ("paid".equalsIgnoreCase(course.getType())) {
        Long userId = UserContext.getUserId();
        UserCourseEnrollment enrollment = enrollmentRepository
            .findByUserIdAndCourseId(userId, courseId);
        
        if (enrollment == null) {
            throw new BizException(ResultCodes.FORBIDDEN, "您未报名该课程");
        }
    }
    
    return chapterRepository.findByCourseIdOrderByOrderIndexAsc(courseId);
}
```

**优先级：** 🟠 **P1 - 高优先级**，付费内容可以被绕过访问，直接影响收入。

### 5. 订单退款流程缺失

**问题描述：**

系统支持取消订单并恢复库存（`OrderService.cancelOrder()`），但：
- ❌ 取消已支付订单时，没有退款流程
- ❌ 没有 `refund` 表或 `payment.refunded_at` 字段
- ❌ 用户的钱无法退回

**当前代码问题：**
```java
// OrderService.cancelOrder()
public void cancelOrder(Long orderId) {
    // ... 检查状态，恢复库存
    order.setStatus("cancelled");
    orderRepository.save(order);
    
    // 😱 如果订单是 paid 状态，钱已经付了，但没有退款操作！
}
```

**业务影响：**
- 用户取消已支付订单，但钱无法退回
- 客服工作量巨大（手动处理退款）
- 用户体验极差，可能引发投诉

**调整建议：**

1. **在 `payment` 表增加退款相关字段（见问题1）**

2. **实现退款流程：**

```java
// PaymentService.java
@Transactional
public void refundPayment(Long orderId) {
    // 1. 查询支付记录
    Payment payment = paymentRepository.findByOrderIdAndStatus(orderId, "success")
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND, "未找到已支付记录"));
    
    // 2. 调用第三方支付平台退款接口
    RefundResult result = thirdPartyPaymentService.refund(
        payment.getTransactionId(), 
        payment.getAmount()
    );
    
    if (!result.isSuccess()) {
        throw new BizException(ResultCodes.INTERNAL_ERROR, "退款失败：" + result.getMessage());
    }
    
    // 3. 更新支付记录
    payment.setStatus("refunded");
    payment.setRefundedAt(new Date());
    paymentRepository.save(payment);
}

// OrderService.cancelOrder() 中调用退款
public void cancelOrder(Long orderId) {
    Order order = orderRepository.findById(orderId)
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND));
    
    // 只有 pending 或 paid 可以取消
    if (!"pending".equals(order.getStatus()) && !"paid".equals(order.getStatus())) {
        throw new BizException(ResultCodes.INVALID_PARAM, "订单状态不允许取消");
    }
    
    // 如果是已支付订单，需要退款
    if ("paid".equals(order.getStatus())) {
        paymentService.refundPayment(orderId);
    }
    
    // 恢复库存
    // ...
    
    // 更新订单状态
    order.setStatus("cancelled");
    orderRepository.save(order);
}
```

**优先级：** 🟠 **P1 - 高优先级**，影响用户资金安全和平台信誉。

## 🟡 次要问题（P2 - 影响功能完整性）

### 6. 课程讲师权限控制缺失

**问题描述：**

`instructor` 表与 `user` 表已经关联（`instructor.user_id`），但：
- ❌ `CourseService.updateCourse()` 和 `deleteCourse()` 没有检查是否是课程的讲师
- ❌ 任何讲师都可以修改/删除其他讲师的课程

**当前代码问题：**
```java
// CourseService.updateCourse()
public Course updateCourse(CourseDTO course) {
    // 😱 任何讲师都可以修改任何课程，无权限检查
    Course nCourse = courseRepository.findById(courseId)
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND));
    BeanUtils.copyProperties(course, nCourse);
    return courseRepository.save(nCourse);
}
```

**业务影响：**
- 讲师的课程可能被其他讲师恶意篡改或删除
- 数据安全问题

**调整建议：**

```java
// CourseService.updateCourse()
public Course updateCourse(CourseDTO courseDTO) {
    if (courseDTO == null || courseDTO.getCourseId() == null) {
        throw new BizException(ResultCodes.NULLPOINT);
    }
    
    Course course = courseRepository.findById(courseDTO.getCourseId())
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND, "课程不存在"));
    
    // 权限检查
    Long currentUserId = UserContext.getUserId();
    
    // 查询课程的讲师
    Instructor instructor = instructorRepository.findById(course.getInstructorId())
        .orElseThrow(() -> new BizException(ResultCodes.NOTFOUND, "讲师不存在"));
    
    // 只有课程的讲师本人或管理员可以修改
    if (!instructor.getUserId().equals(currentUserId) 
        && !UserContext.hasRole(UserRole.ADMIN)) {
        throw new BizException(ResultCodes.FORBIDDEN, "无权修改此课程");
    }
```

```java
// 新增：调整章节顺序
@Transactional
public void reorderChapters(Long courseId, List<Long> chapterIds) {
    // 验证所有章节都属于该课程
    List<Chapter> chapters = chapterRepository.findAllById(chapterIds);
    boolean allBelongToCourse = chapters.stream()
        .allMatch(c -> c.getCourseId().equals(courseId));
    
    if (!allBelongToCourse) {
        throw new BizException(ResultCodes.INVALID_PARAM, "章节不属于该课程");
    }
    
    // 更新顺序
    for (int i = 0; i < chapterIds.size(); i++) {
        Chapter chapter = chapters.stream()
            .filter(c -> c.getChapterId().equals(chapterIds.get(i)))
            .findFirst()
            .orElseThrow();
        chapter.setOrderIndex(i + 1);
        chapterRepository.save(chapter);
    }
}
```

### 10. 订单超时自动取消机制缺失

**问题描述：**

订单创建时库存被扣减，状态为 `pending`，但：
- ❌ 如果用户一直不支付，库存会被永久占用
- ❌ 没有订单超时自动取消的机制
- ❌ 可能导致库存不足但实际未售出

**业务影响：**
- 恶意用户可以通过创建大量订单占用库存
- 其他正常用户无法购买（显示库存不足）

**调整建议：**

1. **实现定时任务：**

```java
// OrderScheduledTasks.java
@Component
public class OrderScheduledTasks {
    
    private final OrderService orderService;
    
    // 每5分钟执行一次
    @Scheduled(cron = "0 */5 * * * ?")
    @Transactional
    public void cancelExpiredOrders() {
        // 查询30分钟前创建的待支付订单
        LocalDateTime expiredTime = LocalDateTime.now().minusMinutes(30);
        
        List<Order> expiredOrders = orderRepository
            .findByStatusAndCreatedAtBefore("pending", expiredTime);
        
        for (Order order : expiredOrders) {
            try {
                // 取消订单（会恢复库存）
                orderService.cancelOrder(order.getOrderId());
                
                log.info("自动取消超时订单: {}", order.getOrderNumber());
            } catch (Exception e) {
                log.error("取消订单失败: {}", order.getOrderNumber(), e);
            }
        }
    }
}
```

2. **在 `order` 表增加过期时间字段（可选）：**

```sql

    COMMENT '订单过期时间（待支付订单30分钟后过期）';
```
